# 安全红线（应用商店审核整改条款 → 长期强制规范）

优先级最高。任何版本、任何功能改动都必须先满足以下 8 条，否则商店审核必驳。

背景：星穹是 LSPosed 模块（`system_server` 内 hook + 模块 App），具备剪贴板读取、
WiFi 密码读取、蓝牙状态改写、root 复制 / 删除安装包等高危能力。审核关注的是
**「高危能力必须有真实门禁与如实披露」——要求补防护，不是删功能**。

---

## 1. 导出组件必须「不导出」或「严格校验发送方」，取不到来源必须拒绝

- 每个 `android:exported="true"` 的组件都要有明确门禁：
  - 首选**签名级自定义权限**：`<permission protectionLevel="signature">` + `<uses-permission>`，
    组件上写 `android:permission`；本应用与同签名应用天然持有，
    `system_server`（uid 1000，core uid）不受组件权限限制，照常可达。
  - 动态注册的接收器用 `registerReceiver(..., broadcastPermission = <签名权限>, ...)`。
- **禁止**把 `getSentFromPackage()` 当作唯一或兜底门禁：
  该 API 在部分 ROM 返回 `null`。「取不到就放行」= 任意应用可触发；
  「取不到就丢弃」= 自家功能全废（7.5 的按钮全部失效即由此而来）。
- 反面案例（5.12 被驳回的入口）：`IslandDeliverReceiver` 导出且不校验发送方；
  `ApkDiscoveryReceiver` 在 Android < 14 不校验、≥ 14 取不到来源仍放行；
  `system` 进程里动态注册的 `LAUNCH` 接收器对外导出且无权限。

## 2. 高危动作必须可归因到「用户点击」

- 关蓝牙、删文件、装安装包、复制 WiFi 密码等动作只能由卡片按钮触发。
- 动作入口必须限定来源（第 1 条）**且**校验参数：路径白名单、电话号码正则、
  URL 仅 `http`/`https` 且长度有上限。
- 一次性口令（token）只能作为补充，不能替代权限门禁。

## 3. 日志：默认关闭、开关必须真的能关、内容必须脱敏

- 应用内开关关掉后，**连框架日志通道（`module.log`）也不许写**。
  「开关只写了 SharedPreferences、日志照写」是明确的驳回项。
- 那不代表日志可以少写：**打码的是身份，记录的必须是事实**。每个环节都要落
  `stage=` 打点（候选来源、类型、后缀、大小、耗时、拒绝原因、结果码），
  否则「日志很干净但查不出问题」等于没日志。
- 日志与报告里禁止出现：完整文件路径、完整网址、WiFi 名称（SSID）、
  蓝牙设备名与 MAC、歌名歌手、剪贴板原文或长度。统一走 `shared/Redact.kt` 的 `Redact.line()`。
- 诊断报告只允许含**本模块**产生的行，不得打包其它模块的框架日志全文
  （先按模块名 / 包名 / TAG 过滤，再脱敏）。
- 开关读取要限频（在 `system_server` 里逐条读偏好是性能红线），
  但限频缓存不能变成「关了还在写」。

## 4. Root 用途说明必须与真实行为逐条一致

- 只读 / 读写要说清。当前真实用途：读 LSPosed 框架日志、读 WiFi 密码、
  root **复制**安装包到暂存、**删除**用户下载的原始安装包、读 `/data/adb` 状态。
- 写成「Root 只用于两件事、均为只读」而实际会复制并删除安装包 = 不实陈述。
- 未授权 root 的影响也要如实：智能文件全链路不可用、WiFi 密码复制/分享不可用，其余照常。

## 5. 隐私披露完整、集中、用户能读到

必须逐项写明：

- 读取**全部**剪贴板内容（默认开启，应用内可关；只有关掉总开关才完全不读，
  只关子开关时仍会读取后比对并立即丢弃）；
- 在音乐应用进程内旁路读取网络响应（嗅探歌词）、改写蓝牙状态查询结果；
- root 读取 WiFi 密码、复制与删除安装包；
- 数据去向（仅本机、不上传）与日志内容、脱敏范围。

落点：应用内「关于 → 如实说明」+ 模块描述（`xposed_description`、
`lyricon_module_description`）+ 商店简介。三处口径必须一致，
不能只写「全部在本机完成」这种概括。

## 6. 商店简介必须如实

审核意见原文：「商店简介未写明读取全部复制内容、在音乐应用内旁路读取网络响应、
使用 root 读取 WiFi 密码与复制/删除安装包」。上架简介必须覆盖这五项。

## 7. 卡片 / 前台服务生命周期必须单一真值

- 卡片 `DismissPolicy` 时长、自动收起定时器、前台服务保活窗口必须是**同一个数值**
  （`ModulePrefs.lingerSecondsFor(prefs, featureOf(kind))`，夹紧 `[10, 150]` 秒）。
- 历史上其一硬编码读 `"link"` 功能时长，导致「卡还在、进程已停」，
  用户表现为「卡放久了按钮全失效」。
- 重复出卡必须做**稳定身份去重**（WiFi 用「连接状态 + SSID」，不能把每次都变的
  测速文本当去重键），并让旧的前台服务定时器作废（generation 计数），
  否则旧的 `stopSelf` 会提前收掉保护窗口。
- 死连接（`IslandClient` / binder）必须可重建，不能 `client ?: new` 之后永远复用坏连接。

## 8. 发布卫生

- release 包不得用 debug 证书；私钥与密码不进发布源码 / 发布包。
- 发布包命名 `项目名 + 版本号（日期）`，附 README；死代码、死资源不得留存。
