# 07 · 错误码与排查

> 来源：`[站点]` <https://astraflow.cc/island/develop-api.html>（`IslandResult` 含义）、`develop-faq.html`（排查结论）；整数码与常量名经 `[SDK]` `astraisland-sdk-0.1.2.aar` 的 `IslandProtocol` 核对。

## 7.1 `IslandResult` 全表（本库唯一权威，03 §3.5 只列协议整数）

| 枚举 | 整数 | 含义 | 常见原因 | 处置 |
| --- | --- | --- | --- | --- |
| `OK` | 0 | 已受理 | — | 未显示不等于没受理，见 §7.3 |
| `NO_PERMISSION` | 1 | 没有投送权限 | 清单中缺少 SDK 自带的权限声明（`com.astraflow.tool.island.permission.PUBLISH_ACTIVITY` 未合并） | 查 [`02-接入与清单.md`](02-接入与清单.md) §2.2、§2.3 |
| `SOURCE_DISABLED` | 2 | 用户在星流中关闭了本应用的内容 | 「外部应用」页关闭了该应用 | 提示用户开启；已显示内容会收到 `onEnded(REMOVED)` |
| `KIND_DISABLED` | 3 | 用户关闭了「星河岛歌词」 | 仅音乐卡片会出现 | 改用非音乐卡片，或提示用户开启 |
| `QUOTA_EXCEEDED` | 4 | 提交且尚未结束的内容已达 3 条 | 排队内容也计入 | 先 `end()` 旧内容（[`06-生命周期与配额.md`](06-生命周期与配额.md) §6.3） |
| `RATE_LIMITED` | 5 | 每秒提交超过 10 次 | `start`/`update`/`end` 都计入 | 合并更新：计时与音乐进度由宿主自行推进，不要逐秒 update（§7.6） |
| `IMAGE_REJECTED` | 6 | **已受理**，但部分图片不合规而未显示，其余照常 | 位图被回收、宽高不在 1~2048、内存 > 8 MB | 见 §7.4；`accepted` 为 `true` |
| `INVALID` | 7 | 内容无效，或连接尚未就绪 | 数值不是有限数（`NaN`/`Infinity`）、字段越界；或 `READY` 之前就提交 | 修正参数；`READY` 后再提交。**原有内容保持不变** |
| `BUSY` | 8 | 星河岛暂时繁忙，本次未处理 | 宿主侧瞬时不可用 | 稍后重试（指数退避），不要立即连打 |
| `NOT_CONNECTED` | 9 | 尚未连接，或连接已断开 | 未 `connect()`、宿主重启、`disconnect()` 之后 | 重新 `connect()` 并等 `READY` |

- `accepted = (result == OK || result == IMAGE_REJECTED)`。
- **受理 ≠ 已显示**：前台隐藏、排位靠后、被收起都会出现「返回 OK 但看不见」。
- 一次调用只返回一个结果：`IMAGE_REJECTED` 优先于 `OK`，其余错误优先于 `IMAGE_REJECTED`。

## 7.2 连接类

| 现象 | 判断顺序 | 处理 |
| --- | --- | --- |
| 状态一直 `WAITING` | 设备已装星流，但星河岛未响应 | 星流中的星河岛未启用；设备刚启动未就绪；**OPPO / 一加 / realme 可能未安装或未启用插件「流体云事件接入」**（插件启用前星河岛不显示）。就绪后客户端**自动连接**，不要重复 `connect()` |
| 状态 `NOT_INSTALLED` | 未装星流，或宿主通信版本 ≠ 7 | SDK 0.1.2 **只连通信版本 7**，高于或低于 7 都不兼容（[`03-通信协议.md`](03-通信协议.md) §3.1） |
| 状态 `REJECTED` | 星河岛核对应用身份未通过 | ① 必须由**应用自身进程**调用 SDK；② AAR 的清单声明已合并进应用（`02` §2.2）；③ 宿主 `com.astraflow.tool` 的 `com.astraisland.HOST_PROTOCOL` == 7（`02` §2.3） |

## 7.3 返回 `OK` 但岛上没有内容

按以下顺序逐条排除：

1. **应用在前台**——默认「进入对应应用时隐藏」为开启，本应用在前台时内容不显示，离开后立即出现；用户关闭该开关后照常显示。应用不能改这个行为（[`06-生命周期与配额.md`](06-生命周期与配额.md) §6.4）。
2. **排位靠后**——更高优先级事项正在显示，本内容在副岛或等待队列中（`06` §6.4）。
3. **被用户收起**——此前应已收到 `onDismissed`；若是「长时间未操作时收起」「停留后收起」导致的自动收起，**不会**收到 `onDismissed`（`06` §6.5）。
4. **锁屏**——按 `LockScreenVisibility` 与系统锁屏通知设置显示（[`04-SDK接口参考.md`](04-SDK接口参考.md) §4.5）。
5. **种类被关**——音乐卡片被关返回 `KIND_DISABLED`；整个应用被关返回 `SOURCE_DISABLED`（`06` §6.7）。
6. **进程/宿主重启**——等 `READY`，用 `listMine()` 核对并重新提交（`06` §6.2）。

## 7.4 图像类

- `IMAGE_REJECTED`：内容已受理，有个别图片不合规被丢弃。检查每张位图：未被回收、宽高各在 1~2048 像素、占用内存 ≤ 8 MB（`04` §4.7）。
- **卡片左侧不显示应用图标**：这是规定，不是缺陷——显示来源栏时来源栏已含图标；卡片图像不接受 `appIcon()`，只有胶囊与副岛可以用；用户关闭来源栏且卡片没有内容图像时，宿主才在左侧显示应用图标（`04` §4.7）。

## 7.5 消息、回复与「标为已读」

| 现象 | 原因与处理 |
| --- | --- |
| 想支持短信回复 | 用 `MessageCard` + `setReplyEnabled(true)`，在 `onReply(activityId, text)` 里真正发送；卡片上的「已交给应用发送」只表示文字已交出，**是否发出由应用确认** |
| 点了「标为已读」没变化 | 标为已读是**应用自定义的按钮**，需要自己 `addButton(TextButton("mark_read", "标为已读"))` 并在 `onAction` 里处理会话状态；星河岛不会自动标已读，`mark_read` 也不是系统保留编号（[`05-卡片数据结构.md`](05-卡片数据结构.md) §5.12） |
| 更新后没重新占据主岛 | 设了 `setPostedAt` 时，**只在收到新消息时改发送时间**；刷新按钮/图片要保留原时间。未设发送时间时，发送人或正文变化才算新消息 |
| 回复期间来了新消息 | 正常现象：编辑或发送期间不替换当前回复卡片，未交出的文字保留为草稿（`06` §6.7 回复保护） |

## 7.6 更新类

- **更新时动画像换了一张卡**：`id` 必须与首次提交一致，编号不同即视为新事项。
- **`RATE_LIMITED`**：每秒 10 次上限；计时与音乐进度由宿主推进，无需逐秒更新；其它进度在明显变化时再更新。
- **`QUOTA_EXCEEDED`**：3 条上限（含排队），先结束已完成的内容。

## 7.7 通知关联

关联了通知却仍有系统横幅：核对 `setOwnNotification(id, tag)` 与 `notify()` 用的编号、标签是否一致；屏蔽横幅还要求该内容**正在主岛或副岛显示**且用户开启「屏蔽系统横幅」，排队或收起期间不屏蔽（[`06-生命周期与配额.md`](06-生命周期与配额.md) §6.8）。

## 7.8 横屏没有标题

横屏不截取卡片标题：数值保留数字与单位，长文本按完整短状态显示，最多四行。需要自定义就用 `setLandscapeText` 提供「数字与英文按组后四行内」的完整短文字；消息显示应用名称，音乐优先显示波形（`06` §6.6）。

## 7.9 从旧接入库升级

早期接入库 `astraisland-client` **已停止提供**，新版星流不再接受其连接，应用自行绘制整张卡片的方式也不再提供。迁移做法：换成星河岛 SDK **0.1.2**，改用 `com.astraisland.sdk` 包中的接口，并把自绘卡片改造成九套模板之一（[`01-概述与环境.md`](01-概述与环境.md) §1.3、[`09-版本变更记录.md`](09-版本变更记录.md)）。

## 7.10 未确认

- `BUSY` 的推荐重试间隔、宿主的重试窗口：站点只说「稍后重试」，**0.1.2 未确认**。
- `INVALID` 的完整触发清单：站点只举「数值不是有限数」与「连接尚未就绪」两例，其余组合校验的边界**0.1.2 未确认**（以 `IllegalArgumentException` 在构造期抛出的为准，见 [`04-SDK接口参考.md`](04-SDK接口参考.md) §4.10）。
- `disconnect()` 后重新 `connect()` 是否保留原内容：站点未说明，**0.1.2 未确认**；稳妥做法是重连后 `listMine()` 核对再重提。
