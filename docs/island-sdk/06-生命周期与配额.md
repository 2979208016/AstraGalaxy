# 06 · 生命周期与配额

> 来源：`[站点]` <https://astraflow.cc/island/develop-limits.html>（数值上限、显示规则）、`design-display.html`（优先级、隐藏与恢复）、`develop-changelog.html`；上限常量经 `[SDK]` `astraisland-sdk-0.1.2.aar` 字节码逐项核对（`IslandProtocol` 的 `MAX_*` 常量）。

## 6.1 数值上限总表（本库唯一权威处，其它文件只引用不重复）

| 项目 | 上限 | SDK 常量 |
| --- | --- | --- |
| 内容编号 | 1~128 字符，不能为空白 | `MAX_ID_CHARS = 128` |
| 按钮编号 | 1~64 字符，不得用保留编号 | `MAX_ACTION_ID_CHARS = 64` |
| 卡片标题、发送者、歌名 | 128 字符 | `MAX_TITLE_CHARS = 128` |
| 说明、歌手 | 256 字符 | `MAX_SUBTITLE_CHARS = 256` |
| 正文、消息内容 | 4096 字符 | `MAX_BODY_CHARS = 4096` |
| 歌词、胶囊右侧文字 | 512 字符 | `MAX_LYRICS_CHARS = 512`、`MAX_SLOT_TEXT_CHARS = 512` |
| 胶囊小标题、横屏短文字、按钮文字、图标按钮说明 | 32 字符 | `MAX_LABEL_CHARS = 32`、`MAX_SHORT_TEXT_CHARS = 32` |
| 短文本：数值、码、明细名称与数值、标签文字、对称名称/比分/小字/中间文字、进度两端文字、阶段名 | 32 字符 | `MAX_SHORT_TEXT_CHARS = 32` |
| 对称下方小字 | 128 字符 | — |
| 读屏说明（`setContentDescription`） | 256 字符 | `MAX_DESCRIPTION_CHARS = 256` |
| 收尾文字（`Outro`） | 128 字符 | `MAX_OUTRO_CHARS = 128` |
| 回复输入 | 2000 字符，输入区最多显示三行 | — |
| **一条内容全部文字合计** | **8192 字节（UTF-8）** | `MAX_TEXT_BYTES = 8192` |
| 每卡明细格子 | 1~6 | `MAX_DETAILS = 6` |
| 每卡阶段名 | 2~16 | `MAX_STAGES = 16` |
| 位图（每张） | 宽高各 1~2048 像素，内存 ≤ 8 MB | `MAX_BITMAP_EDGE_PX = 2048`、`MAX_BITMAP_BYTES = 8388608` |
| 播放速度 | -16~16 | `MAX_PLAYBACK_SPEED = 16` |
| 进度条标签 | 32 字符 | `MAX_PROGRESS_LABEL_CHARS = 32` |

- **字符数按 UTF-16 计**（即 Kotlin `String.length`、Java `String.length()`），与字节数无关；只有「全部文字合计」按 UTF-8 字节计。
- 星河岛接收端截短文字时会保留完整字符与组合表情，不拆开肤色、国旗或组合表情（`[站点]`）。但 SDK 自身在**构造 / `setXxx` / `build()` 时就会抛异常**，不要依赖宿主截短。
- 按钮数量上限（文字 4 / 圆形 3 / 底部图标 4 / 三类合计 4 / 开关 3）见 [`04-SDK接口参考.md`](04-SDK接口参考.md) §4.9，此处不重复。

## 6.2 生命周期

```
创建 IslandClient ──► WAITING ──► READY ──► start / update / end / endAll
       │                │
       │                └─► REJECTED（宿主拒绝，查 02 §2.3）
       └─► NOT_INSTALLED（未安装可用星流，或通信版本不为 7）
```

| 阶段 | 应做的事 |
| --- | --- |
| 启动 | `setCallback(...)` → `connect()`，在 `onStateChanged` 里判断是否 `READY`；**不要**在未连接时反复轮询状态 |
| 连接成功 | 需要恢复的内容按 `listMine()` 核对，再 `start()` 重新提交；被用户收起的内容也要重新提交（收起不等于结束） |
| 运行中 | 内容有变化就 `update()`；结束时 `end()`（可带 `Outro`）或 `endAll()` |
| 宿主重启 / 客户端重连 | 客户端自动重连，状态会重新走 `WAITING → READY`；重连后岛上内容可能已被清空，须靠 `listMine()` 判断 |
| 退出应用 | 想立刻消失就 `end()` / `endAll()` / `disconnect()`；不主动结束的内容按配额与 8 小时上限自然到期 |

- `disconnect()` 会**结束本应用在星河岛上的全部内容**（`[站点]` `develop-api.html`），不只是断开连接。
- 内容被宿主结束时收到 `onEnded(activityId, reason)`，原因取值见 [`04-SDK接口参考.md`](04-SDK接口参考.md) §4.3。
- 由应用自己结束的内容最长显示 **8 小时**（`MAX_LIFETIME_HOURS = 8`），到时自动移除，`DismissPolicy.untilEnded()` 也受此约束。

## 6.3 数量与频率配额

| 项目 | 上限 | 说明 |
| --- | --- | --- |
| 内容条数 | **每个应用 3 条** | 含**暂未显示的排队内容**；星河岛自行读取的同应用通知与音乐**不占**此名额 |
| 提交频率 | **每秒 10 次** | `start`、`update`、`end` **都计入** |
| 自动展开 | 每应用 10 秒内 1 次 | `setAlertOnStart` / `setAlertOnUpdate` 都受此限 |
| 显示时长 | 8 小时 | 见 §6.2 |

- 超出条数或频率返回 `QUOTA_EXCEEDED` / `RATE_LIMITED`（语义见 [`07-错误码与排查.md`](07-错误码与排查.md) §7.1）。
- 连续更新同一事项时显示最新内容；期间提出的自动展开要求**保留一次**，仍受 10 秒一次的限制。
- 想同时显示多条时优先复用同一编号做 `update()`，而不是 `start()` 新编号——后者会占名额并可能触发配额。

## 6.4 排位

主岛同一时间只显示一个事项；多个并存时按优先级决定主岛与副岛，同级中最近开始或更新的优先。

| 级别 | 事项 |
| --- | --- |
| 1 | 来电与通话中；闹钟与计时到点提醒；新收到的消息；用户手动切换到主岛的事项 |
| 2 | 系统导航 |
| 3 | 正在播放的音乐、未到点的计时、外卖与打车等进行中的事项。**第三方应用的内容最高为此级别** |
| 4 | 状态提示：录音、屏幕录制、摄像头与麦克风使用提示、充电、耳机与系统开关。存在这些事项时第三方内容**只能显示为副岛** |

- `Priority.HIGH` 对应「与未到点的计时同档」（级别 3 顶部），**不会**高于来电、通话、新消息与导航；`LOW` 排在正在播放的音乐之后；`DEFAULT` 按卡片种类取默认排位（[`04-SDK接口参考.md`](04-SDK接口参考.md) §4.5）。
- **消息卡片不看 `setPriority`**，按新消息排位：到达时先显示为主岛，经过「消息主岛停留时长」后让位（[`05-卡片数据结构.md`](05-卡片数据结构.md) §5.10）。
- **前台隐藏**：用户开启「进入对应应用时隐藏」（**默认开启**）时，本应用在前台期间其内容在主岛与副岛都不显示，离开后立即恢复；用户可关闭该开关，应用**不能更改**此行为。来电通话、录屏录音、充电等系统状态不受此规则影响；闹钟与计时到点提醒仍可作主岛；锁屏界面覆盖应用时不算前台，内容正常显示在锁屏上。
- **音乐去重**：同一应用同时有 SDK 音乐卡片与星河岛读取的音乐时，只显示 SDK 音乐卡片，另一份进入等待队列。
- **内容隔离**：SDK 内容与星河岛自行读取的通知、音乐分别管理；即使编号相同也不互相替换，应用只能更新/结束自己通过 SDK 提交的内容。

## 6.5 收起、恢复与自动收起

用户可向上或向下划动胶囊把内容从岛上**收起**——胶囊以事项结束的方式收回摄像头，其它事项按优先级接续显示。**来电、正在响铃的计时与闹钟不可收起。**

| 情形 | 是否回调 `onDismissed` | 是否会自己回来 |
| --- | --- | --- |
| 用户手动划走 | **会** | 满足下列任一条件时恢复显示 |
| 用户开启「长时间未操作时收起」或「停留后收起」，超时自动收起 | **不会** | 同上 |

已收起的内容在以下情况恢复：

1. 该事项有**新的提醒**（同一会话收到新消息、计时到点等）；
2. 用户**进入并退出**该事项的来源应用；
3. 星河岛**当前无任何显示内容**时，用户点按摄像头区域。

- 收起**不等于结束**：内容仍占配额名额，`listMine()` 仍能查到；想让它彻底消失用 `end()`。
- 事项结束后不再保留收起状态，再次出现时按新事项显示。
- 应用进程被杀或重连后，收起状态可能已不存在，需按 §6.2 用 `listMine()` 判断并按需重新提交。

## 6.6 场景显示规则

| 场景 | 表现 |
| --- | --- |
| 锁屏 | 显示范围与系统锁屏通知设置及内容声明的 `LockScreenVisibility` 一致；用户可分别关闭锁屏显示与息屏显示。三种可见范围的差别见 [`04-SDK接口参考.md`](04-SDK接口参考.md) §4.5 |
| 下拉通知栏 / 控制中心 | 星河岛收回摄像头，收起后重新显示 |
| 横屏 | 星河岛位于摄像头所在屏幕的一侧，胶囊**纵向**放置，副岛在胶囊上下两端；右侧文字纵向排列，数字与英文按组显示、**最多四行**，保留完整数值/单位/短状态，不截取卡片标题；消息显示来源应用名称，音乐优先显示波形；最右端的附加图像或进度环**在横屏隐藏**；展开卡片内容与竖屏一致 |
| 息屏、下拉通知栏、开启「全屏应用内简化提醒」 | 不自动展开 |
| 勿扰模式 | 被拦截的内容按系统对该内容的限制显示 |

横屏短文字由 `setLandscapeText` 提供，语义见 [`04-SDK接口参考.md`](04-SDK接口参考.md) §4.5；空白、图像、计时与进度环不会被这段文字替换。

## 6.7 内容种类与用户开关

| 卡片 | 归属种类 | 被用户关闭时的结果 |
| --- | --- | --- |
| `MediaCard` | 音乐 | 用户在星流关闭「星河岛歌词」→ 提交返回 `KIND_DISABLED` |
| `MessageCard` | 消息 | 不受星流内容开关影响，只由「外部应用」页按应用管理 |
| 强调卡片中的计时（`EmphasisValue.countdown/stopwatch/paused`） | 计时 | 同上 |
| 其余卡片 | 实时活动 | 同上 |

- 用户可在星流「外部应用」页关闭某个应用的内容；关闭后提交返回 `SOURCE_DISABLED`，**已显示的内容被结束**，`onEnded` 原因为 `REMOVED`。
- 「星河岛歌词」开关只影响音乐卡片；`KIND_DISABLED` 不代表应用被整体禁用。

## 6.8 关联应用自己的通知（`setOwnNotification`）

- 只关联**当前用户**中本应用自己的通知（`NotificationManager.notify` 的编号可加标签）。
- 对应内容保留期间，该通知**不单独上岛**；内容结束后，通知在下次更新时再按通知规则处理。
- 只有内容显示在主岛或副岛、且用户开启「屏蔽系统横幅」时，才屏蔽该通知的系统横幅。
- 注意：SDK 内容与通知是两套独立管理（§6.4 内容隔离），关联只影响显示取舍，不改变归属。
