## 10.2 架构：为什么由模块进程出卡

```
system_server 剪贴板 hook（LinkHook）
  → IslandService.connectAndShow：system 显式 bindService 拉活模块进程
  → 模块进程 LinkHub.showCardFromModule：IslandClient 连星流出卡
  → 点按钮 → 广播 ACTION_LAUNCH 回 system_server → 代发 startActivity
```

每个环节都在它「天然被允许」的进程里执行：检测在系统（hook）、出卡在模块（**uid 与包名一致，宿主的 bind 校验才过**）、跳转在系统（BAL 豁免）。模块进程拉活完成出卡后即可回收，**零常驻**；下次复制再由 system 拉起。

这条链路直接对应规范里的两条硬约束：

- **必须由应用自身进程调用 SDK**——否则宿主 `REJECTED`（[`07-错误码与排查.md`](07-错误码与排查.md) §7.2）。
- **跳转不能在模块进程里 startActivity**——后台启动会被拦，所以只发广播 `ACTION_LAUNCH`（`io.github.proify.astrafirmament.LAUNCH`，`LinkHub.kt:87`、`:718`）。

## 10.3 已落地的实现要点

## 10.4 按钮编号约定（项目内）

`LinkHub` 的 `actionId` 全部为**自定义编号**，均不在 7 个保留编号（`pause`/`resume`/`stop`/`toggle`/`prev`/`play_pause`/`next`）之内，符合 [`04-SDK接口参考.md`](04-SDK接口参考.md) §4.9：

| kind | 按钮 |
| --- | --- |
| phone | `phone_contacts`（保存到通讯录）、`phone_dial`（拨号）、`dismiss`（忽略） |
| link | `open`（打开）、`dismiss`（忽略） |
| wifi（已连接） | `wifi_settings`（查看网络）、`dismiss`（知道了） |
| wifi（密码） | `wifi_pass`（复制密码）、`wifi_share`（分享密码）、`dismiss`（知道了） |
| bt | `bt_disconnect`（断开连接）、`bt_off`（关闭蓝牙）、`bt_settings`（设置）、`dismiss`（知道了） |
| file | `file_share`（分享）、`file_view`（查看）、`file_install`（安装）、`dismiss`（知道了） |

- 每张卡最多 4 个文字按钮（文件卡正好到上限），圆形按钮、开关未使用。
- 0.1.2 起默认每排三个、4 个时 2+2 分两排；**若要保证文件卡四键的固定排法**，可显式加 `setButtonLayout(ButtonLayout(perRow = 2))` 之类，而不是依赖默认值。

## 10.6 本项目特有注意事项

- **模块清单里声明了 debug 宿主的权限与查询**（`app/src/main/AndroidManifest.xml:16`、`:33`，`com.astraflow.tool.debug`）。规范只要求 release 宿主的声明；debug 条目保留是为了调试宿主，不影响 release。
- **不要在模块进程里调用 `listMine()` 做状态轮询**：进程随时可能被回收，客户端随之消失；状态判断靠 `isReady()` 与 `start()` 的返回结果。
- **`disconnect()` 会结束本应用全部内容**——本项目没用它做「卡片消失」的手段（那样会连别的卡一起杀掉）；单卡结束用 `end(CARD_ID)`，进程回收后重开时用临时 `IslandClient` 结束（`LinkHub.kt:351` 附近的注释即此原因）。
- **开关闸门**在出卡前检查（`isKindAllowed`）：总开关 + 子开关任一关闭即拦。这是项目侧策略，与 SDK 无关；但注意被拦时**不要**调用 `connect()`，避免无意义地连上宿主。
- **WiFi 卡去重键**必须剥离「实测网速」，否则 `CONNECTIVITY_ACTION` 抖动会导致反复重出卡、重排收起任务、前台服务提前 `stopSelf`，表现为「卡还在但按钮点不动」。
