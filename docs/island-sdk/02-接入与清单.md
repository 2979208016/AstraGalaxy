# 02 · 接入与清单

> 来源：`[站点]` <https://astraflow.cc/island/develop-quickstart.html>、`develop-faq.html`、`develop-overview.html`；`[SDK]` `astraisland-sdk-0.1.2.aar` 内 `AndroidManifest.xml`
>
> 接入代码的完整写法见 [`08-示例代码.md`](08-示例代码.md)；本节只讲「工程怎么配、清单要不要改、连不上时先查什么」。

## 2.1 接入三步（`[站点]` `develop-quickstart.html`）

1. **添加 SDK**：把 `astraisland-sdk-0.1.2.aar` 放进 `libs/` 并加依赖，清单声明自动合并。
2. **选择模板**：按事项性质从九套模板里挑一套（选型表见 [`01-概述与环境.md`](01-概述与环境.md) §1.3），填写胶囊与卡片内容。
3. **发送与更新**：事项开始时发送，状态变化时以同一编号更新，完成后结束，并处理用户操作。

## 2.2 清单：无需手动修改

`[站点]` 原文：

> 「**清单**无需手动修改。构建时自动合并发送权限与宿主查询声明；发送权限为普通权限，安装时即授予，不弹出授权窗口。」

官方示例工程的 `app/src/main/AndroidManifest.xml` 也确实**没有声明任何权限**，只有 `<application>` 与 `MainActivity`（`[SDK]` `astraisland-sdk-sample-0.1.2`）：

```xml
<?xml version="1.0" encoding="utf-8"?>
<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <application
        android:label="星河岛 SDK 示例"
        android:theme="@android:style/Theme.Material.Light">
        <activity android:name=".MainActivity" android:exported="true">
            <intent-filter>
                <action android:name="android.intent.action.MAIN" />
                <category android:name="android.intent.category.LAUNCHER" />
            </intent-filter>
        </activity>
    </application>
</manifest>
```

### 工具包自动合并的声明（`[SDK]`，AAR 内清单原文）

```xml
<manifest xmlns:android="http://schemas.android.com/apk/res/android"
    package="com.astraisland.sdk" >

    <uses-sdk android:minSdkVersion="26" />
    <!-- 星河岛 SDK：接入应用构建时自动合并以下声明，无需手动添加。 -->
    <uses-permission android:name="com.astraflow.tool.island.permission.PUBLISH_ACTIVITY" />

    <queries>
        <package android:name="com.astraflow.tool" />
    </queries>
</manifest>
```

合并后接入应用实际获得：

| 声明 | 值 | 作用 |
| --- | --- | --- |
| `<uses-permission>` | `com.astraflow.tool.island.permission.PUBLISH_ACTIVITY` | 投送权限。**普通权限**，安装时即授予，无授权弹窗 |
| `<queries><package>` | `com.astraflow.tool` | Android 11+ 包可见性，用于查询宿主是否安装及其 `meta-data` |
| `minSdkVersion` | `26` | Android 8.0 |

工具包其余内容（`[SDK]`）：`R.txt`（空）、`classes.jar`（`com.astraisland.sdk` 与 `com.astraisland.protocol` 两个包）、`META-INF/com/android/build/gradle/aar-metadata.properties`（`aarFormatVersion=1.0`、`minCompileSdk=26`、`minAndroidGradlePluginVersion=1.0.0`、`coreLibraryDesugaringEnabled=false`）。

> 权限字符串站点正文未给出，上面来自 AAR 清单原文，属 `[SDK]` 证据。
>
> 若接入方自行编写清单（不使用 AAR 自动合并、或做 manifest 裁剪），缺少该权限会导致提交返回 `NO_PERMISSION`（`IslandResult` 语义见 [`07-错误码与排查.md`](07-错误码与排查.md) §7.1）。

## 2.3 四处校验

| 校验点 | 规则 | 失败后果 | 来源 |
| --- | --- | --- | --- |
| 发送权限 | 清单须含 `PUBLISH_ACTIVITY`（SDK 自动合并） | `IslandResult.NO_PERMISSION` | `[站点]` `[SDK]` |
| 宿主通信版本 | 宿主 `meta-data` 须为 7 | `State.NOT_INSTALLED`（视为「不支持的宿主」） | `[站点]` `[SDK]` |
| 会话通信版本 | 连接后回传版本 ≠ 7 | `State.REJECTED` | `[SDK]` `IslandClient.bind()` |
| 应用身份 | 须「由自身进程调用 SDK」且清单声明已合并 | `State.REJECTED` | `[站点]` `develop-faq.html` |

### 宿主查询的实现（`[SDK]` `IslandClient.isHostInstalled()`）

```java
getPackageInfo("com.astraflow.tool", 0x80)   // GET_META_DATA
  → applicationInfo.metaData.getInt("com.astraisland.HOST_PROTOCOL", 0) == 7
```

即：宿主 `com.astraflow.tool` 的 `<application>` 内声明 `meta-data android:name="com.astraisland.HOST_PROTOCOL"`，其整数值必须为 `7`，否则一律视为未安装可用宿主。

`develop-faq.html` 对 `REJECTED` 的原文解释：

> 「状态是 REJECTED：星河岛核对应用身份未通过。请确认应用由自身进程调用 SDK，且工具包的清单声明已合并到应用中。」

> `[未确认]` 星流具体如何核对身份（签名摘要、uid、包名三者如何比对）站点未说明，**不要臆测**。可确认的是「必须由应用自身进程调用」——这条约束对多进程或注入式架构影响很大，星穹的做法见 [`10-项目对接备忘.md`](10-项目对接备忘.md)。

## 2.5 接入自检清单

- [ ] `libs/` 下有 `astraisland-sdk-0.1.2.aar`，`build.gradle.kts` 已 `implementation(files(...))`
- [ ] `compileSdk >= 26`、`minSdk = 26`、Java 17、Kotlin 2.1+
- [ ] 未手动删除合并进来的 `PUBLISH_ACTIVITY` 权限与 `<queries>` 声明（可查 merged manifest 确认）
- [ ] 设备为 Android 15+，已装并启用星流；OPPO / 一加 / realme 已启用「流体云事件接入」插件
- [ ] `IslandClient` 在**应用自身进程**创建
- [ ] 提交调用（`start` / `update` / `end` / `endAll` / `listMine`）不在主线程
- [ ] 已处理 `NOT_INSTALLED` 分支：功能入口隐藏，应用照常运行
